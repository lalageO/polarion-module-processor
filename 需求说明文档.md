# Polarion module.xml 本地解析与替换模块需求说明文档 V1

# 1. 模块定位

本模块是一个**独立 Java/Spring Boot 工具模块**，用于本地处理 Polarion 导出的 `module.xml` 文件。

第一版目标是跑通以下闭环：

```
用户上传 module.xml
  ↓
模块读取 XML 文件
  ↓
提取 <field id="homePageContent"> 中的 CDATA HTML 内容
  ↓
识别其中的 <p> 段落
  ↓
筛选候选需求段落
  ↓
生成处理结果 JSON
  ↓
生成预览 CSV
  ↓
按 mock Work Item ID 或外部映射 ID 替换 <p> 为 module-workitem div
  ↓
输出 processed_module.xml
```

第一版不做：

1.  不接入公司 FDP 系统。
2.  不从 Polarion 网页 URL 自动拉取 `module.xml`。
3.  不处理 Polarion 登录认证。
4.  不调用真实 Polarion API 创建 Work Item。
5.  不调用真实 LLM。
6.  不自动写回 Polarion。
7.  不建数据库表。
8.  不做前端页面，使用后端接口或本地接口测试即可。

------

# 2. 第一版核心目标

### 2.1 必须实现

1.  支持本地上传 `module.xml`。
2.  正确解析外层 XML。
3.  正确提取 `homePageContent` 字段中的 CDATA HTML。
4.  正确识别 CDATA 内的 `<p>` 段落。
5.  能从 `<p>` 中提取：
    -   `paragraphId`
    -   `outlineNo`
    -   `sourceText`
    -   `sourceOuterHtml`
    -   `sourceTextHash`
    -   `sourceOuterHtmlHash`
6.  按规则筛选候选需求段落。
7.  生成 `import_result.json`。
8.  生成 `import_preview.csv`。
9.  生成替换后的 `processed_module.xml`。
10.  支持 dry-run 预览模式。
11.  支持 mock Work Item ID 替换模式。
12.  保留后续接入真实 LLM 和真实 Polarion API 的扩展点。

### 2.2 第一版验收核心

第一版完成后，输入一个真实 `module.xml`，应能输出：

```
output/{jobId}/
  ├── original_module.xml
  ├── processed_module.xml
  ├── import_result.json
  └── import_preview.csv
```

其中 `processed_module.xml` 中，候选 `<p>` 应被替换为：

```
<div id="polarion_wiki macro name=module-workitem;params=id=MOCK-000001"></div>
```

或者如果后续传入真实映射 ID，则替换为：

```
<div id="polarion_wiki macro name=module-workitem;params=id=FDP-7021"></div>
```

# 3. 输入与输出

## 3.1 输入文件

用户上传一个 `module.xml` 文件。

典型结构：

```
<?xml version="1.0" encoding="UTF-8"?>
<module>
    <field id="author">pingping.xu</field>
    <field id="created">2026-05-22 14:44:41.262 +0800</field>
    <field id="homePageContent" text-type="text/html">
        <![CDATA[
            <p id="polarion_137" style="margin-left: 160px;">
              4.4. There shall be affixed...
            </p>
        ]]>
    </field>
    <field id="status">draft</field>
    <field id="title">R171e2</field>
</module>
```

关键点：

-   外层是 XML。
-   真正的文档 HTML 内容在 `field id="homePageContent"` 的 CDATA 中。
-   目标 `<p>` 标签位于 CDATA 内部。

------

## 3.2 输出文件

每次运行生成一个任务目录：

```
output/{jobId}/
  ├── original_module.xml
  ├── processed_module.xml
  ├── import_result.json
  └── import_preview.csv
```

示例：

```
output/R171e2_20260526_153000/
  ├── original_module.xml
  ├── processed_module.xml
  ├── import_result.json
  └── import_preview.csv
```

| 文件                   | 作用                      |
| ---------------------- | ------------------------- |
| `original_module.xml`  | 原始上传文件备份          |
| `processed_module.xml` | 替换 `<p>` 后的新 XML     |
| `import_result.json`   | 程序可读的任务状态账本    |
| `import_preview.csv`   | 人工可读的段落预览/验收表 |

# 4. 接口设计

## 4.1 上传并处理接口

```
POST /api/module/process
Content-Type: multipart/form-data
```

## 4.2 请求参数

| 参数              | 类型          | 必填 | 默认值            | 说明                       |
| ----------------- | ------------- | ---- | ----------------- | -------------------------- |
| `file`            | MultipartFile | 是   | 无                | 上传的 `module.xml`        |
| `moduleName`      | String        | 否   | 从 XML title 推断 | 文档名，例如 `R171e2`      |
| `dryRun`          | Boolean       | 否   | `true`            | 是否只预览                 |
| `replaceMode`     | String        | 否   | `NONE`            | 替换模式                   |
| `mockIdPrefix`    | String        | 否   | `MOCK`            | mock Work Item ID 前缀     |
| `includeSubItems` | Boolean       | 否   | `false`           | 是否处理 `(a)`、`(b)` 子项 |
| `requireKeyword`  | Boolean       | 否   | `true`            | 是否要求包含需求关键词     |
| `minOutlineDepth` | Integer       | 否   | `2`               | 条款号最小层级             |
| `titleMode`       | String        | 否   | `RULE_BASED`      | 标题生成模式               |

------

## 4.3 replaceMode 取值

| 值        | 说明                                                         |
| --------- | ------------------------------------------------------------ |
| `NONE`    | 不替换 XML，只生成 JSON 和 CSV                               |
| `MOCK`    | 使用 mock Work Item ID 替换 `<p>`                            |
| `MAPPING` | 使用外部传入的真实 Work Item ID 映射替换，第一版可预留，非必须实现 |

第一版必须实现：

```
NONE
MOCK
```

`MAPPING` 可先预留接口，后续实现。

------

## 4.4 请求示例

### dry-run 预览

```
curl -X POST "http://localhost:8080/api/module/process" ^
  -F "file=@D:/polarion/module.xml" ^
```

# 5. 处理流程

## 5.1 dry-run 流程

```
上传 module.xml
  ↓
保存 original_module.xml
  ↓
读取 XML 原文字符串
  ↓
提取 homePageContent CDATA 内容
  ↓
解析 CDATA 中的 HTML 片段
  ↓
扫描所有 <p>
  ↓
提取段落信息
  ↓
执行候选规则判断
  ↓
生成规则标题
  ↓
生成 import_result.json
  ↓
生成 import_preview.csv
  ↓
不生成替换内容，或 processed_module.xml 与原文件一致
```

dry-run 不应修改 XML 逻辑内容。

------

## 5.2 mock 替换流程

```
上传 module.xml
  ↓
保存 original_module.xml
  ↓
提取 homePageContent CDATA
  ↓
扫描并筛选候选 <p>
  ↓
为候选段落生成 mock Work Item ID
      MOCK-000001
      MOCK-000002
      MOCK-000003
  ↓
生成 replacementHtml
  ↓
在原始 CDATA 字符串中替换目标 <p>
  ↓
将新 CDATA 写回 module.xml
  ↓
输出 processed_module.xml
  ↓
输出 import_result.json
  ↓
输出 import_preview.csv
```

# 6. XML 与 HTML 解析策略

## 6.1 不建议整体重写 XML

为避免破坏 Polarion 文件格式，第一版采用**局部字符串替换策略**。

原则：

1.  原始 `module.xml` 整体作为字符串读取。
2.  只定位并替换 `homePageContent` CDATA 内部内容。
3.  不整体重新序列化 XML。
4.  不改动其他 `<field>`。
5.  不改动非目标段落。

------

## 6.2 提取 CDATA

通过正则定位：

```
(?s)(<field\s+id="homePageContent"[^>]*>\s*<!\[CDATA\[)(.*?)(\]\]>\s*</field>)
```

分组含义：

| 分组    | 含义       |
| ------- | ---------- |
| group 1 | CDATA 前缀 |
| group 2 | HTML 内容  |
| group 3 | CDATA 后缀 |

处理方式：

```
newModuleXml = group1 + newHtmlContent + group3
```

要求：

1.  如果找不到 `homePageContent`，任务失败。
2.  如果找不到 CDATA，任务失败。
3.  不要把 CDATA 内容 XML 转义成 `<p>`。

------

## 6.3 HTML 解析

CDATA 内部是 HTML 片段，使用 Jsoup 解析：

```
Document doc = Jsoup.parseBodyFragment(htmlContent);
doc.outputSettings()
    .prettyPrint(false)
    .syntax(Document.OutputSettings.Syntax.html);
```

Jsoup 用于：

1.  查找 `<p>`。
2.  提取 `p.id()`。
3.  提取 `p.text()`。
4.  判断是否空段落。
5.  判断是否需求候选。

------

## 6.4 替换策略

Jsoup 只用于识别和提取，不直接使用 Jsoup 序列化后的 HTML 作为最终输出。

替换时回到原始 `htmlContent` 字符串中，根据 `paragraphId` 查找原始 `<p>` 片段。

针对每个目标段落，使用正则：

```
(?s)<p\b(?=[^>]*\bid=["']polarion_162["'])[^>]*>.*?</p>
```

其中 `polarion_162` 替换为当前段落 ID。

替换为：

```
<div id="polarion_wiki macro name=module-workitem;params=id=MOCK-000001"></div>
```

注意：

1.  默认认为 `<p>` 内不会嵌套另一个 `<p>`。
2.  每个 `paragraphId` 应唯一。
3.  替换前计算原始 `<p>` 片段 hash。
4.  替换后更新 JSON 状态。

------

# 7. 段落提取字段

每个 `<p>` 应提取为一个 `ImportItemResult`。

## 7.1 字段清单

| 字段                  | 示例                                | 说明                      |
| --------------------- | ----------------------------------- | ------------------------- |
| `seq`                 | `87`                                | 扫描顺序                  |
| `paragraphId`         | `polarion_162`                      | `<p>` 的 id               |
| `outlineNo`           | `5.3.3.`                            | 条款号                    |
| `paragraphKey`        | `R171e2#polarion_162#sha256:abcd`   | 幂等 key                  |
| `sourceText`          | `5.3.3. The system may activate...` | 纯文本                    |
| `sourceTextHash`      | `sha256:abcd`                       | 文本 hash                 |
| `sourceOuterHtml`     | `<p id="...">...</p>`               | 原始 p 片段，可不写入 CSV |
| `sourceOuterHtmlHash` | `sha256:efgh`                       | 原始 p 片段 hash          |
| `candidate`           | `true`                              | 是否候选需求              |
| `skipReason`          | `TITLE_ONLY`                        | 跳过原因                  |
| `generatedTitle`      | `系统应按需激活相关车辆系统`        | 生成标题                  |
| `finalTitle`          | `系统应按需激活相关车辆系统`        | 最终标题                  |
| `workItemId`          | `MOCK-000001`                       | mock 或真实 ID            |
| `replacementHtml`     | `<div id="..."></div>`              | 替换内容                  |
| `status`              | `REPLACED`                          | 状态                      |
| `errorCode`           | `null`                              | 错误码                    |
| `errorMessage`        | `null`                              | 错误信息                  |

------

# 8. 候选段落筛选规则

## 8.1 默认候选规则

一个 `<p>` 被识别为候选需求，需要满足：

1.  有 `id`，且格式类似：

    ```
    polarion_162
    ```

2.  文本非空。

3.  文本以数字条款号开头，例如：

    ```
    4.4.
    5.1.1.
    5.3.2.1.
    ```

4.  条款号层级大于等于 `minOutlineDepth`。

    默认：

    ```
    minOutlineDepth = 2
    ```

    例如：

    | 文本                           | 层级 | 默认是否候选 |
    | ------------------------------ | ---- | ------------ |
    | `5. General Specifications`    | 1    | 否           |
    | `5.1. General Requirements`    | 2    | 视关键词判断 |
    | `5.1.1. The system shall...`   | 3    | 是           |
    | `5.3.2.1. The system shall...` | 4    | 是           |

5.  如果 `requireKeyword=true`，文本中必须包含需求关键词。

------

## 8.2 条款号提取正则

```
^\s*(\d+(?:\.\d+)+\.?)
```

示例：

| 原文                                | outlineNo        |
| ----------------------------------- | ---------------- |
| `5.3.3. The system may activate...` | `5.3.3.`         |
| `4.4. There shall be affixed...`    | `4.4.`           |
| `5. General Specifications`         | 不匹配或层级不足 |

------

## 8.3 需求关键词

默认关键词列表：

```
shall
should
must
may
is required to
are required to
shall be designed
shall aim to
is intended to
are intended to
```

大小写不敏感。

------

## 8.4 跳过规则

| 场景                   | skipReason               |
| ---------------------- | ------------------------ |
| 段落为空               | `EMPTY_PARAGRAPH`        |
| 没有 id                | `NO_PARAGRAPH_ID`        |
| id 不是 `polarion_xxx` | `INVALID_PARAGRAPH_ID`   |
| 不含条款号             | `NO_OUTLINE_NO`          |
| 条款号层级不足         | `OUTLINE_DEPTH_TOO_LOW`  |
| 不含需求关键词         | `NO_REQUIREMENT_KEYWORD` |
| 纯章节标题             | `TITLE_ONLY`             |
| 目录内容               | `TOC`                    |
| 其他非需求文本         | `NOT_REQUIREMENT_LIKE`   |

第一版可以先不做复杂目录识别，仅通过条款号层级和关键词过滤目录。

------

# 9. 标题生成规则

第一版不调用真实 LLM，使用规则生成标题。

## 9.1 titleMode

| 值              | 说明                       |
| --------------- | -------------------------- |
| `RULE_BASED`    | 默认，基于原文生成简短标题 |
| `SOURCE_PREFIX` | 使用原文前若干字符作为标题 |
| `MOCK`          | 生成固定 mock 标题         |
| `LLM`           | 预留，第一版不实现真实调用 |

------

## 9.2 RULE_BASED 默认策略

处理逻辑：

1.  去掉开头条款号。
2.  去掉多余空格和 ` `。
3.  截取前 40 个字符。
4.  拼接条款号。

示例：

原文：

```
5.3.3. The system may activate relevant vehicle systems when necessary and applicable...
```

生成标题：

```
5.3.3 The system may activate relevant vehicle systems
```

如果后续接 LLM，再生成中文标题，例如：

```
系统应按需激活相关车辆系统
```

第一版不强制中文标题。

------

## 9.3 标题长度

默认最大长度：

```
80 字符
```

超过则截断，并去掉末尾不完整空白。

# 10. Work Item ID 生成规则

第一版不调用真实 Polarion API，因此使用 mock ID。

## 10.1 mock ID 格式

```
{mockIdPrefix}-{6位序号}
```

默认：

```
MOCK-000001
MOCK-000002
MOCK-000003
```

示例：

```
<div id="polarion_wiki macro name=module-workitem;params=id=MOCK-000001"></div>
```

## 10.2 后续真实 ID

后续如果接入 Polarion API，应把 mock ID 替换为真实返回 ID：

```
FDP-7021
FDP-7022
```

第一版代码中应保留接口：

```
public interface WorkItemIdProvider {
    String provide(ImportItemResult item, int index);
}
```

默认实现：

```
MockWorkItemIdProvider
```

后续实现：

```
PolarionWorkItemIdProvider
```

# 11. 替换规则

## 11.1 原始段落

```
<p id="polarion_162" style="margin-left: 160px;">
  5.3.3. The system may activate relevant vehicle systems when necessary...
</p>
```

## 11.2 替换后

```
<div id="polarion_wiki macro name=module-workitem;params=id=MOCK-000001"></div>
```

## 11.3 注意事项

1.  只替换完整 `<p>...</p>`。
2.  不保留原 `<p>` 的 `style`。
3.  不把原文塞进 `<div>`。
4.  不生成浏览器控制台中的复杂运行时 DOM。
5.  不处理已存在的 `module-workitem` `<div>`。
6.  替换后的宏结构必须严格为：

```
<div id="polarion_wiki macro name=module-workitem;params=id={workItemId}"></div>
```

# 15. 错误处理

## 15.1 文件上传失败

处理：

```
{
  "success": false,
  "message": "module.xml upload failed"
}
```

------

## 15.2 找不到 homePageContent

错误码：

```
HOME_PAGE_CONTENT_NOT_FOUND
```

处理：

1.  任务失败。
2.  不生成 processed XML。
3.  返回错误信息。

------

## 15.3 找不到 CDATA

错误码：

```
CDATA_NOT_FOUND
```

处理：

1.  任务失败。
2.  返回错误信息。

------

## 15.4 HTML 解析失败

错误码：

```
HTML_PARSE_FAILED
```

处理：

1.  任务失败。
2.  保存原始文件。
3.  返回错误信息。

------

## 15.5 某个 `<p>` 替换失败

错误码：

```
PARAGRAPH_REPLACE_FAILED
```

处理：

1.  当前 item 标记为 `REPLACE_FAILED`。
2.  继续处理其他 item。
3.  最终 `failedCount + 1`。
4.  在 CSV 中记录错误原因。

# 18. 核心类职责

## 18.1 ModuleProcessController

职责：

1.  接收 MultipartFile。
2.  接收处理参数。
3.  调用 `ModuleProcessService`。
4.  返回处理结果。

------

## 18.2 ModuleProcessService

职责：

1.  编排完整流程。
2.  保存原始文件。
3.  调用 XML 提取器。
4.  调用段落扫描器。
5.  调用候选筛选器。
6.  调用标题生成器。
7.  调用 ID provider。
8.  调用 XML rewriter。
9.  调用 JSON/CSV writer。

------

## 18.3 ModuleXmlExtractor

职责：

1.  从 `module.xml` 字符串中提取 `homePageContent` CDATA。
2.  返回：
    -   `prefix`
    -   `htmlContent`
    -   `suffix`
    -   `fullXmlContent`

------

## 18.4 ParagraphScanner

职责：

1.  用 Jsoup 解析 HTML。
2.  扫描全部 `<p>`。
3.  提取：
    -   `paragraphId`
    -   `sourceText`
    -   `outlineNo`
4.  根据 `paragraphId` 从原始 HTML 中提取原始 `<p>...</p>` 片段。
5.  计算 hash。

------

## 18.5 ParagraphCandidateSelector

职责：

1.  根据规则判断是否候选。
2.  给出 `skipReason`。
3.  不负责生成标题。
4.  不负责替换 XML。

------

## 18.6 RuleBasedTitleGenerator

职责：

1.  第一版生成规则标题。
2.  后续可被 LLM 实现替换。

------

## 18.7 MockWorkItemIdProvider

职责：

1.  为候选 item 生成 mock ID。
2.  格式：`MOCK-000001`。

------

## 18.8 ModuleXmlRewriter

职责：

1.  根据 `paragraphId` 查找原始 `<p>`。
2.  替换为 `replacementHtml`。
3.  生成新的 HTML 内容。
4.  写回原始 XML 的 CDATA 中。

------

## 18.9 ImportResultWriter

职责：

1.  输出 `import_result.json`。
2.  使用 Jackson 格式化输出。
3.  UTF-8 编码。

------

## 18.10 ImportPreviewCsvWriter

职责：

1.  输出 `import_preview.csv`。
2.  UTF-8 with BOM 可选，方便 Excel 打开。
3.  字段按需求固定顺序输出。

------

# 21. 验收标准

## 21.1 dry-run 验收

输入：

```
module.xml
dryRun=true
replaceMode=NONE
```

期望：

1.  接口返回 `success=true`。
2.  输出 `original_module.xml`。
3.  输出 `import_result.json`。
4.  输出 `import_preview.csv`。
5.  `processed_module.xml` 可以不生成，或内容与原始文件一致。
6.  不出现 mock Work Item ID。
7.  CSV 中能看到候选段落和跳过原因。

------

## 21.2 mock 替换验收

输入：

```
module.xml
dryRun=false
replaceMode=MOCK
```

期望：

1.  接口返回 `success=true`。
2.  输出 `processed_module.xml`。
3.  候选 `<p>` 被替换为 `module-workitem` div。
4.  替换格式为：

```
<div id="polarion_wiki macro name=module-workitem;params=id=MOCK-000001"></div>
```

1.  非候选段落保持不变。
2.  `import_result.json` 中记录每条候选段落的 mock ID。
3.  `import_preview.csv` 中记录每条段落的状态。

------

## 21.3 文件格式验收

1.  输出 XML 保持 UTF-8。
2.  `homePageContent` 仍然是 CDATA。
3.  非 `homePageContent` 字段不应被重写。
4.  原始 XML 外层结构不应明显变化。
5.  替换后的 XML 可以被文本编辑器正常打开。

------

## 21.4 候选规则验收

以下文本应识别为候选：

```
5.3.3. The system may activate relevant vehicle systems when necessary...
5.3.4. The system’s control strategy shall be designed to reduce...
5.1.1. The system shall be designed to ensure...
```

以下文本默认应跳过：

```
5. General Specifications
5.3.5. Response to System boundaries
Contents
UNITED NATIONS
<p><br></p>
```

# 23. 第一版开发顺序

建议 Codex 按以下顺序实现：

## 阶段一：项目骨架

1.  创建 Spring Boot 项目。
2.  创建上传接口。
3.  实现文件保存。
4.  返回基本响应。

## 阶段二：CDATA 提取

1.  读取 XML 原始字符串。
2.  定位 `homePageContent`。
3.  提取 CDATA HTML。
4.  异常处理。

## 阶段三：段落扫描

1.  引入 Jsoup。
2.  扫描全部 `<p>`。
3.  提取文本和 ID。
4.  提取条款号。
5.  生成 hash。

## 阶段四：候选判断

1.  实现筛选规则。
2.  实现 skipReason。
3.  生成 item 列表。

## 阶段五：JSON/CSV 输出

1.  输出 `import_result.json`。
2.  输出 `import_preview.csv`。
3.  检查字段完整性。

## 阶段六：mock 替换

1.  生成 mock Work Item ID。
2.  生成 replacementHtml。
3.  替换原始 HTML 中目标 `<p>`。
4.  写回 CDATA。
5.  输出 `processed_module.xml`。

## 阶段七：测试和修正

1.  用真实 `module.xml` 测试。
2.  检查 CSV。
3.  检查 XML diff。
4.  修正候选规则。
